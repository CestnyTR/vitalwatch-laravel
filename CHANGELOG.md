# Changelog

> **Rename:** The package has been renamed to VitalWatch — Composer package
> `cestnytr/vitalwatch-laravel`, namespace `CestnyTR\VitalWatch`, config
> `config/vitalwatch.php`, command `vitalwatch:status`, environment variables `VITALWATCH_*`,
> signature headers `X-VitalWatch-Signature` / `X-VitalWatch-Timestamp`.
> The history below uses the new names.

Semver. The hub's ingest endpoint contract is kept backward compatible: new
fields may be added, existing fields are never removed. Older package versions
keep working.

```bash
composer require cestnytr/vitalwatch-laravel
```

## 0.2.6

### Changed

- Docs: README, CHANGELOG and package description are now in English.
- All user-visible output (CLI, log warnings, IDE docs) is now in English:
  `vitalwatch:status` labels and messages, the published `config/vitalwatch.php`
  comments, and PHPDoc summaries on the public classes.
- **Fingerprint side effect:** messages the SDK generates itself are now in English —
  fatal error labels (`Fatal error: …`, `Parse error: …`, `Compile error: …`, …), queue job
  timeouts (`Queue job timed out: <job> (60 s)`) and the `vitalwatch:status --test` probe
  (`Test event generated by vitalwatch:status --test`). These events are grouped under a
  new fingerprint once after upgrading; a new row appears in the panel and you may get one
  "new error" alert.
- When the installed version cannot be read, `sdk_version` is now `unknown`
  (was `isUnknown`).

## 0.2.5

### Changed

- **Plain CamelCase names are no longer turned into `[token]`.** The long-string mask
  (24+ characters) mistook class and method names such as `InvalidOperationException` and
  `HandleNonSuccessAndDebuggerNotification` for tokens, making stack traces unreadable.
  A candidate that contains no digits or `-`/`_` and fully matches
  `^[A-Za-z][a-z]+(?:[A-Z][a-z]+)+$` is no longer treated as a token. Real tokens and
  session IDs almost always contain digits; strings with digits, consecutive capitals or
  all caps are masked as before. The rule is identical to the hub and the other SDKs.
- **Fingerprint side effect:** error messages containing such a name are grouped under a
  new fingerprint once after upgrading; a new row appears in the panel and you may get one
  "new error" alert.

## 0.2.4

### Added

- **Queue jobs that time out are reported** (`JobTimedOut`).
  When a job had run out of attempts, Laravel marked it as failed and `JobFailed` fired;
  when attempts remained, however, the worker process was killed by a signal and nothing
  reached the panel. Yet a job that times out signals a problem even if a retry succeeds:
  the queue backs up and the process dies on every round.

  Because Laravel marks the job as failed before dispatching the event, there was a risk
  of two records; a per-job flag is kept so only one record is created. No stack: no
  exception is thrown.

## 0.2.3

### Added

- **Automatic release tag.** If `VITALWATCH_RELEASE` is empty, CI/PaaS variables are read
  in order (`GIT_COMMIT`, `GIT_SHA`, `COMMIT_SHA`, `SOURCE_VERSION`,
  `VERCEL_GIT_COMMIT_SHA`, `RENDER_GIT_COMMIT`, `HEROKU_SLUG_COMMIT`,
  `CI_COMMIT_SHA`), then `.git` in the project root (branch, packed-refs, detached HEAD,
  `gitdir:` file). The commit is shortened to its first 12 digits. No shell command, no
  caching (an FPM worker survives a deploy). The hub can now show which deploy introduced
  an error. The rule is the same in all three packages.
- **`vitalwatch:status` shows the release tag and its source**
  (`source: VITALWATCH_RELEASE | <VARIABLE> | .git | none`).
- **`vitalwatch:status` update check.** Prints the newest stable release on Packagist; if
  the installed one is older, it suggests `composer require
  cestnytr/vitalwatch-laravel:^X.Y` (a warning; the exit code does not change). Without
  network access it prints `could not check`; `VITALWATCH_STATUS_OFFLINE=1`
  skips it.
- **Environment name normalization.** The hub only accepts production/staging/local and
  drops anything else — liveness pings included — with a 204. A project set up with
  `APP_ENV=development` or `prod` looked as if it sent nothing. Aliases are now mapped
  (`prod`/`live`, `stage`/`stg`/`preprod`/`uat`, `dev`/`development`/`test`/`testing`);
  unrecognized values are sent as is and the diagnostic command reports an error.
  The table is the same in all three packages.
- **Error reporting no longer delays the response.** In a measured HTTP request, error and
  slow-query events are held until terminate; previously `report()` could wait on the hub
  up to the timeout before the response. In processes that never reach terminate, they are
  sent at shutdown.
- **`job_failed`.** The README had listed it for ages, but it was never sent. A job that
  runs out of attempts is recorded via the `JobFailed` event; the same error that Laravel
  then passes to the handler is deduplicated.
- **`command_failed`.** Failed scheduled tasks (including non-zero exit codes). Silent
  cron failures are now visible. The PHP binary path is stripped from the task name and
  the message (`artisan report:send`), so that a path differing between servers does not
  split the same task into two rows. Laravel fires no failure event for
  `runInBackground()` tasks — see the README.
- **Liveness from queues and the scheduler.** An app that only runs queues or the
  scheduler never sees an HTTP request, so the liveness request was never sent and the
  installation looked "silent".
- **Octane.** Workers run under the CLI, so request measurement was never installed. It is
  now; the request time is used instead of `LARAVEL_START` (otherwise every request would
  look as "slow" as the worker's lifetime). Counters are reset at the end of each request
  and when a queue job starts. The recorder is resolved at boot: the per-request
  application clones Octane creates share a single instance (otherwise hooks and
  measurement wrote to different instances, and request records always showed a query
  count of 0).

### Fixed

- **`vitalwatch:status` alignment.** Labels were padded by bytes, so lines with Turkish
  characters (`Paket sürümü`, `Proje anahtarı`) were misaligned.
- **One failure produced two records.** Besides the `exception` with a stack, a failing
  request also created a stackless `http_5xx` from the measuring middleware. The request is
  now flagged, and no `http_5xx` is created for a flagged request.
- **Error records had no route or method.** The panel did not show which endpoint failed;
  "Path" stayed `/`. The pattern is now sent (`/api/products/{id}`).
- **New errors could be swallowed in long-running processes.** Deduplication used an array
  of `spl_object_id`s; IDs are reused after garbage collection and the array was never
  cleared. In a queue worker, a new error that got the same ID was considered "already
  reported". Switched to a `WeakMap`.
- **Logged 4xx errors reached the hub.** The package also listens to the log event; when
  the application logged a caught 404 with `Log::warning(..., ['exception' => $e])`,
  Laravel's dontReport list was bypassed. `HttpException` with 400–499 and
  `ModelNotFoundException` are no longer reported.
- **`VITALWATCH_TIMEOUT` unit.** It was read with `(int)`: `0.5` became zero — an
  unlimited wait in curl. Since the Node package expects milliseconds under the same name,
  setting `2000` could make the PHP process wait 2000 seconds. It is now seconds, with 100
  and above treated as milliseconds; invalid, zero, negative or infinite values become 2 s;
  the result is clamped to 0.1–10 s (the same rule across all SDKs). The `_MS` curl options
  and `CURLOPT_NOSIGNAL` are used.
- **8 KB limit.** The hub drops oversized bodies without reading them and still returns
  204. Since fields were truncated by characters, a stack containing 3–4 byte characters
  could exceed the limit. Now the stack is dropped first, then the message, then the
  slowest query. Invalid UTF-8 no longer drops the body (`JSON_INVALID_UTF8_SUBSTITUTE`).
- **E-mail addresses were not masked in text containing invalid UTF-8.** The e-mail
  pattern uses the `/u` flag; on broken bytes the pattern was silently skipped and the
  address went through as is (e.g. a latin1 database error). The text is now repaired with
  `mb_scrub` first.
- **The synchronous queue wiped the request's measurements.** A job on a `sync`/`deferred`
  connection runs inside the request; the reset at job start erased the request's start
  time and lost `slow_request` and `http_5xx`, and liveness could make a network request
  before the response. For these jobs the reset and liveness are skipped; the `job_failed`
  record is kept.
- **Long job class names became `[token]`.** The class name in a `job_failed` route is no
  longer masked (it is not personal data); different jobs used to collapse into a single
  row in the panel. Scheduled task names are still masked.
- **An error thrown before routing under Octane** did not flag the request; the same
  failure also created an `http_5xx`.
- **Masking mangled readable names.** Upload file names now stay readable. Names of the
  form `<name>-<timestamp>-<random>.jpeg` showed up in the panel as
  `/uploads/discount/[token][card]-752066249.jpeg`: the timestamp was taken for a card
  number and the long name for a token.

  - **Card:** only sequences starting with 2–9 that pass Luhn are masked. No card network
    starts with 0/1, while millisecond timestamps start with 1. Known trade-off: card
    numbers that fail Luhn (typos) and UATP cards starting with 1 are no longer masked.
  - **Token:** a hex string containing an unbroken segment of 16+ characters, or letters,
    (UUIDs, hashes) is masked. Short segments joined by hyphens are readable names.
    Known trade-off: random keys split into short segments by hyphens/underscores (e.g.
    some base64url tokens) may slip through. Both trade-offs were accepted on purpose to
    keep file names readable.
  - **Phone:** no match when preceded by a digit. A timestamp whose last ten digits start
    with 5 used to become `179[phone]`.

  The rules are identical in the hub, `t.js`, Node, Laravel and Python; compared against
  28 shared test vectors.

## 0.2.0

**Hub requirement — important for this release.** Fatal errors are sent with kind `fatal`,
and the hub's list of allowed kinds must include it. If you upgrade before updating the
hub, **fatal errors are silently dropped**: the ingest endpoint returns 204 even for an
invalid event, and no trace is left anywhere. Deploy the hub first.

The liveness ping also needs the liveness columns migration; if it is missing, the
liveness request does no harm, it is simply not recorded.

### Added

- **Fatal error capture.** Out-of-memory errors, timeouts and compile errors do not throw
  exceptions in PHP: the process dies and the exception handler never runs. The class of
  errors that **actually takes a site down** had never reached the panel — the uptime probe
  saw the 500, but nobody knew why.

  They are caught with `register_shutdown_function` and sent with kind `fatal`, not
  `exception`: one is a condition the application can catch, the other means the server
  hit a limit, and this class needs to be filterable on its own.

  A 256 KB buffer is reserved at boot and released at shutdown. When memory runs out, the
  reporting code itself has no room to run; without the buffer the hook is installed but
  silently fails exactly when it is needed.

  Only fatal types are sent (`E_ERROR`, `E_PARSE`, `E_CORE_ERROR`,
  `E_COMPILE_ERROR`, `E_USER_ERROR`). Warnings and notices can be raised dozens of times
  per request and would flood the panel.

- **Liveness ping.** A request carrying no events is sent every eight hours. The hub used
  to tell whether an installation was working only from incoming errors; an app running
  without errors looked like a "broken installation".

  It is **not tied** to Laravel's scheduler: the package is installed in dozens of
  projects and a running cron cannot be assumed in all of them. It is sent during
  `terminate()`, after the response has been sent; if it is not due yet, only a cache read
  happens.

  Side benefit: the hub's own uptime probe is a request too, so even a site with no
  visitors keeps its pulse.

### Fixed

- The `Recorder` configuration was missing the project key. Since the liveness cache is
  scoped by that key, two applications sharing a cache store would suppress each other's
  pulse.
